# 提弗洛斯渲染还原：从零独立学习图谱

这套教材的用途：即使没有任何模型服务、聊天记录或代写工具，你也能沿着文件、命令、原理、练习和验收记录，独立复现目前做成的部分，并继续推进尚未完成的官方管线。它不是一串提示词，也不要求接入任何 AI 插件。

范围：Windows、Unity 2022.3.30f1、提弗洛斯角色详情页、已有本地资源与 frame 6411 的离线捕获。模型/材质/四族主颜色的已验收基线为 Git `1b25951`。完整动态阴影、姿态、官方最终画面仍须逐关验证；不要把“教材覆盖了终点”误读为“工程已经到终点”。

## 总技术图谱

读法：纵向是必须按顺序通过的关卡，横向是并行学习的基础；括号中的字是必须保存的产物。没有产物和验收，不算过关。

```text
文件/PowerShell ─┬─ Python/JSON/二进制 ─┐
Git/备份 ───────┤                    │
向量/矩阵/坐标 ─┼─ C#/Unity Editor ───┼─ 0. 建独立练习工程
颜色/纹理采样 ──┘                    │   （版本表、三角形、最小测试）
                                    ▼
1. 原始包 → 格式识别 → 解包/导出 → 按对象ID建立资产索引
   （原文件哈希、工具版本、资产清单，绝不直接覆盖源文件）
                                    ▼
2. Mesh → 坐标/索引/法线/UV → Bone路径与映射 → bindpose/权重
   （模型JSON、静止蒙皮恒等式、范围/有限性检查）
                                    ▼
3. 持久化Unity网格/骨架 → 材质JSON → 纹理槽与颜色空间 → 深度/剔除
   （可保存重开的场景、TBN、每槽ST、角色部件身份）
                                    ▼
4. 离线RDC → Event/Pass → 实际纹理绑定 → 常量字节偏移 → Shader候选
   （证据表，不按文件名/大小/外观直接认定变体）
                                    ▼
5. 最小平面上的HLSL → CPU手算 → GPU读回 → 再接角色
   ├─ skin：LUT、SDF、mask、GGX、rim
   ├─ hair：RGorAG、切线、双各向异性、LineMap
   ├─ cloth：ramp alpha、P图、specRamp、emission、IBL
   └─ eye：球面/视差、matcap、透明度与光照mask的区别
   （32组数值基线 + 整个人物回归）
                                    ▼
6. 管线对齐：Cubemap各面/mip + 角色自阴影atlas + Pass顺序/覆盖层
   （资源导出清单、坐标对应、生成算法，不能贴静态截图代替动态）
                                    ▼
7. HDR → 9级Bloom → sharpen/vignette → LogC → 官方LUT → sRGB/dither
   （相同HDR输入上的全帧数值比较；再换成Unity实时输入）
                                    ▼
8. 同姿态/镜头/裁剪/分辨率/曝光的官方对照 → 分区误差 → 转身/运动回归
   （固定基准图、误差报告、验收清单、可回退Git提交）
```

## 每一关的退出条件

| 关卡 | 你要能独立回答的问题 | 必须交付的东西 |
|---|---|---|
| 0 基础 | 点、方向、法线为什么不能同样变换？0.5线性灰为什么不是sRGB0.5？ | 三角形练习工程和说明 |
| 1 解包 | 这个对象来自哪个包、哪个 PathID、哪个版本？ | 完整资产清单与哈希 |
| 2 几何 | 哪个矩阵把顶点带到哪个空间？权重索引指向谁？ | 静止蒙皮数值报告 |
| 3 材质 | 这张图每个通道在 Shader 的哪一行使用？ | 每部位材质契约表 |
| 4 捕获 | 当前事件是主颜色、深度、阴影还是覆盖层？ | draw/资源/常量/候选表 |
| 5 Shader | 换成已知常量输入后，GPU为什么应输出这个数？ | CPU/GPU 对照测试 |
| 6 光照管线 | 阴影来自什么几何、矩阵、深度比较和滤波？ | 可随相机/角色变化的正确结果 |
| 7 后处理 | 哪个阶段是线性HDR，哪里只做一次sRGB编码？ | 捕获输入重放误差报告 |
| 8 官方效果 | 差异来自姿态、材质、光照还是后处理？ | 固定条件下的分层验收证据 |

本轮推进：官方环境cube保留6面/8mip，6面GPU采样通过；选定后处理在相同官方HDR输入上整帧RGB误差≤1个8-bit色阶；动态17-dispatch Bloom最终相对L1误差约0.0271%。第04章给出独立实时场景的构建、重载与验收入口。

需要继续攻克：本帧 G 通道角色自阴影的生成、动态姿态与镜头的精确对齐、局部覆盖层/透明与材质dither、环境反射在完整角色上的最终一致性、最终全帧一致性。不能用已经通过的单Pass实验掩盖这些剩余任务。

## 第一晚的具体安排

- 建一个不含游戏资源的 `TyphoeusLearning` 练习文件夹和 Git 库。
- 跑一个 Python 脚本，打印一个 JSON 的字段名与数值范围；再故意改坏索引，让脚本报错。
- 在 Unity 空场景创建并保存一个三角形 Mesh，重新打开后验证它还在。
- 自己手算 `dot((0,0,1),(0,.6,.8))=.8`，让 Shader 输出这个灰度，读取像素核对。
- 写下今天的版本、输入、结果和一个未解决问题。通过这四项再碰真实角色。

不是按“看完多少教程”计进度，而是按“能独立解释、复现、排错多少关”计进度。

## 使用资料的规则

本教材优先链接源码、数据和官方 API，而不是让你寻找一段神奇参数。C# 语言新教程可能使用 Unity 2022 不支持的新语法；这里只需掌握该工程实际使用的 C# 特性。[微软 C# 学习入口](https://learn.microsoft.com/zh-cn/dotnet/csharp/tour-of-csharp/)。

回退前先理解工作树、暂存区和提交；本机 main 与记录分支不同，不能直接强制切换。[Pro Git 中文版](https://git-scm.com/book/zh/v2)。
