## 本轮查实的错误

### 组件身份、材质和坐标

使用 `.ini` 中的 buffer stride/format，逐顶点比较 mod 与 `_typhoea_model_data.json`。数据结果：

| mod 组件 | 正确对应 | 顶点数 | 最大位置误差 | 最大 UV 误差 | 旧导入器的问题 |
|---|---|---:|---:|---:|---|
| C0 | cloth_05，角 | 1060 | 5.93e-8 | 4.23e-8 | 当成脸删除，直接导致缺角 |
| C1 | hair_01 | 15306 | 5.95e-8 | 4.04e-8 | 使用了正确头发贴图，但把辅助贴图与 mod 贴图一起翻 UV |
| C3 | face_01 | 2109 | 5.95e-8 | 4.46e-8 | 当成小件并套眼白材质 |
| C6 | iris_01，瞳孔 | 162 | 5.23e-8 | 4.24e-8 | 错认其高度异常后删除 |
| C7 | eyeshadow_01 | 40 | 4.97e-8 | 3.16e-8 | 属于专用眼影覆盖层，不是额外瞳孔 |

脸的真实高度范围为 1.23479–1.42091，瞳孔为 1.29660–1.32280。此前拿角的 1.39601–1.62797 范围当成脸，才得出“瞳孔落位错误”。

C13/C14 的 VB0 **40 字节**、VB1 **8 字节**；分别是 140/498 顶点、420/1566 索引。按 16 字节读取产生的 ±1 范围来自错读法线等字段，不能作为数据坏掉的证据。它们采用 `gpu_posed=0` 的不同空间，本轮使用原 JSON 的 638 顶点眉部作为静态替代，并非声称完成了 mod 运行时蒙皮。

`.ini` 明确指定 C3/C13/C14 使用 `6b12e27e` 图集，C0/C2/C10 使用 `28ef925d` 配件图集。旧版把后者当作脸图，是黑脸/错贴图的重要原因。C3 和 C6 的 UV 与官方逐点一致，**没有证据支持“脸 UV 被重排，所以必须烘焙另一张脸”**。

本轮恢复 C0、C2、C3、C6；使用正确模板和图集；停用重复烘焙脸部的菜单实现，⑦改为校验。所有部件统一采用 `(x,z,-y)`，保留源坐标原点，不再分别按整体包围盒平移后拼接另一个场景的脸。

复核另发现旧列表同时绘制互斥的 `Main=0/1` 和 `Socks=0/1` 片段。新增检查先复现失败，再按 INI 默认 `Main=0, Socks=1` 移除 C8 的 `first=10404/54396/117732` 三段，避免重叠服装。保留的透明围裙仍采用近似不透明路径，完整 dither 尚待实现。

### UV 与法线

保留网格原始 UV。仅给 DDS 转成 PNG 的 mod 贴图设置 `(scale=1,-1; offset=0,1)`。原有 SDF、Emotion、Highlight 和官方法线等辅助贴图继续用原始 UV。Shader 的 BaseMap、BumpMap、MetallicGlossMap 各自使用自己的 ST，描边同步使用 BaseMap ST。

这是一条针对本批导出文件的转换约定，不能泛化成“D3D 的所有 UV 都必须翻转”或“Unity 是 OpenGL”。法线/PBR 数据图设为 Default + Linear 保留原通道，交给 shader 解码。未变更几何的部件保留官方法线；C8 读取声明中的浮点法线。

### 官方帧常量与 shader

纠正 `_CharacterParams0/2/5/15` 抄录，补齐 `3/4/14` 和完整环境向量。常量由 `EndfieldOfficialFrameGlobals` 持续设置，重开场景也能生效；显式 profile 开关控制捕获帧光方向/光色/强度。

光色依据实际变体：face b138 使用 CP4，body b401 的函数体第 904 行使用 CP5。不能因本地材质分类 `_MaterialFamily=1` 就把 body 改成 CP4；该分类不是官方 shader 身份证据。

skin b138 的函数体直接使用 `_ShadowLutTex` 插值结果 `_504`，没有读取声明中的 `_ShadowColorBrightness/Saturation`。原实现再次乘亮度会把捕获值 brightness=0 的皮肤阴影归零；本轮移除这次错误调制。

这些修复**不是完整光照公式移植**：环境合成、ramp/SDF、头发半程向量、后处理仍有近似路径。
