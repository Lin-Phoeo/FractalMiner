# 终末地 RenderDoc 社区资料核验

核验日期：2026-09-17。目标仍为提弗洛斯角色详情页。本文是检索与后续验证计划，
不是本机抓帧成功报告；本轮没有安装或运行第三方抓帧器，没有修改游戏或保护组件。

## 结论

确实存在作者声称成功抓取终末地的第一手资料。此前本机标准 RenderDoc 被
`1-18000` 拒绝，只能证明那一次尝试失败，不能推导出游戏无法被任何人抓帧。
然而，本轮未取得可回放的提弗洛斯 `.rdc`，也未验证社区方案兼容本机当前版本。
研究记录必须分开标注「作者报告」「仓库能力说明」「本机验证」。

## 对还原工程有用的进一步资料

### 描边不仅是把模型扩大

[Floraison：终末地的角色描边（2026-04-14）](https://www.floraison.io/2026/04/14/)
是另一个可读的第一手分析。作者讨论裁剪空间外扩，以及环境光、LUT、Ramp、
角色自阴影和边缘调色共同参与描边颜色的过程。

本机 `Assets/EndfieldShaderPack/EndfieldCharacterLit.shader` 的 Outline pass 已修复
世界米制外扩问题，但片元颜色仍是基色、饱和度与亮度的简化实现。这与文章描述
存在明确差距；修好炸模并不等于已经恢复官方描边。文章的缓冲槽号和单帧常量不能
直接硬编码到我们的 Unity 工程，需要先与本地版本的 shader dump 和具体变体对应。

### 抓帧与自动分析是两个阶段

[JinxiangW/renderdoc-mcp 当前 README](https://github.com/JinxiangW/renderdoc-mcp)
写明支持打开的 qrenderdoc 会话与离线 `.rdc` 分析，并支持多窗口选择。
这比五月文章的单窗口说明更新，安装或集成时应以核实后的仓库版本为准。
[功能树](https://github.com/JinxiangW/renderdoc-mcp/blob/master/docs/feat-tree.md)
列有绘制调用、管线状态、shader 绑定与常量、网格和纹理检查能力；本轮没有实测。

该工具分析已有捕获，不是凭空获得原游戏 GPU 帧，也不会自动生成完整 Unity 工程。
若集成，应先在我们自己的 Unity 捕获上验证，不提前修改全局 MCP 配置。

## 后续验证顺序（尚未执行）

1. 记录精确游戏版本、实际图形 API、画质、分辨率、HDR、曝光和角色姿势。
   不能把社区 DX11 案例直接当成本机 Vulkan 成功案例，也不能假设通用启动参数一定有效。
2. 优先核验能实际回放的参考捕获。需要提供捕获来源、版本与允许分析的范围。
   任何新的第三方工具运行方案须另行说明实际操作与风险，本报告不执行它。
3. 从提弗洛斯关键部位的 draw call 建立证据表：shader 变体、纹理与采样器、
   常量缓冲、顶点格式、深度/模板/混合状态、前置阴影与后处理依赖。
4. 对齐一个确定的相机与姿势，先比较中间缓冲，再比较最终输出；随后检查转角、
   距离与运动变化，防止只拟合一张截图。解码压缩顶点时保留原始位模式，避免低精度
   文本导出破坏数据；不对已经正确解码的本地 mesh 重复解码。
5. 每个通过验证的改动独立提交。游戏捕获、含账号信息的截图和第三方程序不上传仓库。

单帧只提供那个时刻实际执行的 GPU 工作与资源，不代表游戏全部场景、动态系统和
所有 shader 变体。因此验收目标是可复核地缩小与官方参考的差异，而不是无证据承诺完美。
